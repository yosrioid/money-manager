# v0.3.0-beta.1 - Phase 3 And Phase 4 Private Beta

## Release Summary

- **Release type:** Milestone prerelease
- **Status:** Prerelease
- **Published:** Pending publication
- **Target commit:** Release-preparation merge commit
- **Scope:** Phase 3 `P3-01` to `P3-21` and Phase 4 `P4-01` to `P4-25`

## Highlights

- Delivers a full daily-use transaction experience: history, calendar,
  weekly, monthly, and summary views with search, filters, sorting, infinite
  scroll, transaction detail with audit log, bulk draft duplication, and
  workspace-scoped day notes.
- Delivers fast-entry productivity: reusable transaction bookmarks, recent
  description/merchant suggestions, favorite accounts/categories, a
  configurable entry-form field order, an amount-focused keyboard-driven entry
  flow, swipe/arrow-key period navigation, and a per-transaction
  "include in statistics" toggle.
- Delivers per-category monthly budgets (expense and income) with per-month
  overrides, carryover, on-pace tracking, and weekly/yearly/trend views.
- Delivers a workspace net-asset target and a reports dashboard (summary,
  category/merchant/account breakdowns, period comparison, net worth and net
  worth trend) with configurable widgets and filters.
- Delivers CSV and Excel export of transactions and reports, a validated and
  idempotent CSV/Excel transaction import flow with a preview step, and an
  asynchronous queued large-CSV export with re-authorized background
  generation.

## Financial Integrity

- All new budget, report, and net-asset calculations are read-only and
  derived from existing posted, balanced ledger entries
  (`include_in_statistics`-aware, excluding `Replaced` transactions); no
  ledger posting, balance, or audit semantics changed.
- Transaction import reuses the existing `RecordIncomeExpense` posting path
  and idempotency-key mechanism, so imported transactions are subject to the
  same balancing, validation, and audit guarantees as manually entered ones;
  re-imports of the same file are detected and skipped as duplicates.
- All new budget, report, import, and export endpoints are scoped to the
  active workspace and authorized via Laravel Policies
  (`CategoryPolicy`, `TransactionExportPolicy`); the queued export job
  re-checks that its creator is still a workspace member before generating a
  file.

## Security

- Fixed a CSV/formula-injection issue in
  `GenerateTransactionsCsv::writeTransaction`: `description`, `memo`,
  merchant/account/category names, and tags are now escaped when they start
  with `=`, `+`, `-`, `@`, tab, or CR before being written to CSV, covering
  both immediate and queued exports. Covered by a regression test.
- Cross-workspace access to budgets, overrides, reports, transaction exports,
  and imports is denied and covered by automated tests.
- Composer and npm (`--audit-level=high`) audits reported no known
  vulnerabilities during release preparation.

## Database And Upgrade Notes

- This prerelease adds: `day_notes`, `transaction_bookmarks`,
  `category_budget_overrides`, and `transaction_exports` tables; `is_favorite`
  on `accounts` and `categories`; `entry_form_fields`,
  `navigation_shortcuts_enabled`, `net_asset_target`, and `report_widgets` on
  `workspaces`; `include_in_statistics` on `transactions`; and
  `monthly_budget_amount`/`budget_carryover_enabled` on `categories`.
- Adds the `phpoffice/phpspreadsheet` dependency (Excel export/import).
- Back up any existing database before upgrading.
- Run `php artisan migrate --force --isolated` during deployment.
- Restart long-running Laravel services (including queue workers) after
  deployment, since `P4-25` introduces a new queued job
  (`GenerateTransactionsExportFile`).

## Known Limitations

- This is a private beta milestone, not an MVP or production-readiness
  release.
- Transaction import supports income/expense rows only; transfers are not
  importable in this version.
- Advanced accounts (cards, debt, assets, multi-currency), automation,
  attachments, backup/restore, and collaboration workflows are not included.
- Phase 8 production hardening and release-readiness gates have not run.

## Rollback

- Prefer restoring the pre-release database backup and previous application
  version together.
- Do not selectively remove or mutate posted, reversed, replaced, or imported
  transactions or their entries.
- Migration rollback is suitable only for disposable or verified
  pre-production data, since this release's migrations add columns and tables
  referenced by budgets, reports, imports, and exports.

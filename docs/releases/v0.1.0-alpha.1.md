# v0.1.0-alpha.1 - Phase 1 Internal Alpha

## Release Summary

- **Release type:** Milestone prerelease
- **Status:** Prerelease
- **Published:** Pending publication
- **Target commit:** Release-preparation merge commit
- **Scope:** Phase 0 foundation and Phase 1 `P1-01` to `P1-34`

## Highlights

- Delivers secure registration, authentication, personal workspace isolation,
  preferences, application lock, and starter financial presets.
- Delivers account groups, accounts, categories, merchants, tags, ordering,
  archiving, visibility controls, and balanced immutable opening balances.
- Replaces the starter welcome screen with an original Money Manager landing
  page.

## Included Scope

- `F-001` and `F-002`: Laravel/Vue foundation, governance, CI, static analysis,
  and browser testing.
- `F-003`: Authentication, sensitive-action security, personal workspace,
  active context, and cross-workspace isolation.
- `F-004`: Currency, timezone, locale, number format, week start, and custom
  month preferences.
- `F-005`: Account groups and accounts, including ordered, visible, archived,
  total-inclusion, and opening-balance behavior.
- `F-006`: Categories, subcategories, appearance, merchants, tags, application
  lock, and starter presets.
- `F-021`: Branded public landing page.

## Financial Integrity

- Monetary amounts use integer minor units.
- Opening balances post atomically as balanced immutable transactions against
  opening-balance equity entries.
- Account balances derive from posted ledger entries.
- Financial and reference-data operations are authorized and workspace scoped.
- General income, expense, transfer, reversal, and replacement workflows remain
  Phase 2 scope.

## Security

- Authentication, email verification, password reset, password confirmation,
  two-factor authentication, passkeys, and application-lock journeys are
  included.
- Cross-workspace access denial is covered by automated tests.
- The critical development dependency advisory through
  `concurrently -> shell-quote` was remediated before release preparation.
- Composer and npm audits reported no known vulnerabilities during Phase 1
  acceptance verification.

## Database And Upgrade Notes

- This prerelease introduces workspace, membership, currency, account,
  reference-data, application-lock, transaction, and transaction-entry schema.
- Back up any existing database before upgrading.
- Run `php artisan migrate --force --isolated` during deployment.
- Ensure the supported currency reference data is seeded for existing
  installations.
- Restart long-running Laravel services after deployment.
- This release does not provide an automated production deployment or database
  rollback workflow.

## Known Limitations

- This is an internal alpha milestone, not an MVP or production-readiness
  release.
- General income, expense, transfer, reversal, transaction-history, reporting,
  budget, import/export, advanced account, automation, attachment, and
  collaboration workflows are not included.
- Phase 8 production hardening and release-readiness gates have not run.

## Rollback

- Prefer restoring the pre-release database backup and previous application
  version together.
- Do not selectively remove or mutate posted opening-balance transactions.
- Migration rollback is suitable only for disposable or verified pre-production
  data because Phase 1 migrations create and transform financial structures.

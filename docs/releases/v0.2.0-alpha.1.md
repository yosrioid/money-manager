# v0.2.0-alpha.1 - Phase 2 Core Ledger Alpha

## Release Summary

- **Release type:** Milestone prerelease
- **Status:** Prerelease
- **Published:** Pending publication
- **Target commit:** Release-preparation merge commit
- **Scope:** Phase 2 `P2-01` to `P2-24`

## Highlights

- Delivers the double-entry ledger foundation: balanced posted transactions,
  integer minor-unit money, transaction lifecycle states, atomic posting,
  concurrent-write account locking, immutable posted entries, reversal and
  replacement corrections, an immutable financial audit log, and posted-only
  account balance calculation (current and as-of-date).
- Delivers core income, expense, and account-transfer entry, including
  transfer fees, cash withdrawal and credit-card settlement transfer
  workflows, transaction date/time, merchant or recipient, memo, and tags.
- Delivers split transactions across multiple categories, safe
  calculator-style amount expressions, save-as-draft, draft resume and
  update, and transaction duplication into a new draft.

## Included Scope

- `F-007`: Double-entry ledger foundation (`P2-01` to `P2-10`) - lifecycle
  enum and transition guard, posted-only balance and balance-at-date
  calculation, immutable audit log, account locking, reversal, and
  replacement.
- `F-008`: Core transaction flows (`P2-11` to `P2-24`) - income, expense,
  transfer, transfer fee, cash withdrawal, credit-card settlement, transaction
  metadata (date/time, merchant, memo, tags), split transactions, calculator
  amount expressions, drafts, and duplication.

## Financial Integrity

- Every posted transaction balances to zero in its base currency; unbalanced
  or malformed entries are rejected before any write occurs.
- Money is stored as integers in minor units; amount expressions are
  evaluated with safe integer arithmetic only.
- Account balances are derived only from posted ledger entries; draft,
  voided, and replaced transactions do not affect balances.
- Posted entries, transactions in terminal lifecycle states, and audit log
  entries are immutable; corrections use auditable reversal and replacement
  transactions that preserve category and account references.
- Ledger writes run inside database transactions and lock affected accounts;
  a workspace-scoped idempotency key prevents duplicate posting from replayed
  submissions and rejects conflicting payloads reusing the same key.
- Posting, reversal, replacement, draft, and duplication actions are
  authorized against workspace membership and reject archived or
  cross-workspace account, category, merchant, and tag references.

## Security

  merchants, and tags is denied and covered by automated tests.

## Database And Upgrade Notes

- This prerelease adds the `audit_logs` and `transaction_tags` tables, and
  adds correction-link, category, metadata, draft-data, and idempotency-key
  columns to the transaction tables.
- Back up any existing database before upgrading.
- Run `php artisan migrate --force --isolated` during deployment.
- Restart long-running Laravel services after deployment.
- This release does not provide an automated production deployment or
  database rollback workflow.

## Known Limitations

- This is an internal alpha milestone, not an MVP or production-readiness
  release.
- Transaction history, navigation, search, filters, fast-entry, dashboards,
  budgets, statistics, reports, import/export, advanced accounts, automation,
  attachments, and collaboration workflows are not included.
- Phase 8 production hardening and release-readiness gates have not run.

## Rollback

- Prefer restoring the pre-release database backup and previous application
  version together.
- Do not selectively remove or mutate posted, reversed, or replaced
  transactions or their entries.
- Migration rollback is suitable only for disposable or verified
  pre-production data because Phase 2 migrations create and transform
  financial ledger structures.
